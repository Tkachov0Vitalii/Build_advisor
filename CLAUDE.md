# Build Advisor — Slay the Spire 2 mod

In-game RU/EN deck advisor: scores card rewards, shop items, relic choices and event card screens against the current deck. C# / .NET 9, Harmony patches over the game's Godot nodes, data from spire-codex.com plus bundled models trained on 177k runs.

The owner speaks Russian: reply in Russian. Code, comments and commit messages are in English. All user-facing text is written in Russian first and translated to English through the dictionary in `src/ModLocalization.cs` (see "Localization").

## Commands

```powershell
# build (finds the game in the default Steam folder; otherwise -p:Sts2ManagedDir=<data_sts2_windows_x86_64>)
dotnet build BuildAdvisor.csproj -c Release
# offline regression matrix (must print Regression=True)
dotnet run --project tools/RegressionRunner -c Release
# full release: version check, -warnaserror build, regression, Harmony target check, ZIP + SHA256SUMS
powershell -ExecutionPolicy Bypass -File tools\make_release.ps1      # Windows
tools/make_release.sh                                                # Linux/macOS/Git Bash
```

Game assemblies for builds outside the game folder live in `tools/bin/Debug/net9.0` (`sts2.dll`, `GodotSharp.dll`, `0Harmony.dll`, `sts2.xml`). They are references only and are never packaged or committed (`.gitignore`). After a game update copy fresh ones from `C:\Program Files (x86)\Steam\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64` and run the release script: the Harmony step lists hooks the update broke.

Installed mod: `<game>\mods\build-advisor\`. Since 7.0 the release ZIP holds one folder `build-advisor/` (mod files, `fonts/`, docs) and is extracted straight into `mods/`; the Workshop ZIP holds the uploader workspace (`publish/workshop` + `content/`). The game log line to check: `Build Advisor <version> loaded; all patches installed; regression matrix passed.`

## Layout

- `src/` — the mod. Entry point `BuildAdvisorMod.Initialize` installs each Harmony patch class separately (one renamed game method must not disable the rest).
- `src/RunContextReader.cs` — reads the run by reflection: local player (`LocalContext.GetMe`, co-op safe), deck with duplicates and upgrade levels (`CardStates` is index-aligned with `Cards`), relics, HP, gold, route, run seed.
- `src/DeckBuildScoring.cs` — the score: community baseline (Codex Score) + deck adjustments (`Adjust(value, label)`; every adjustment appears in the formula). Also `RelicKnowledge` (relic roles taken from the game assembly).
- `src/TakeSkipModel.cs` — take/skip in percentage points of win rate. `WinDelta` = distance to the take threshold (≥ 0 → take): (lift − centre) × 6 / spread + deck adjustments × 0.19 − bar, where centre/spread = median/IQR of lifts of the character's own cards in the metrics in use (`Scale`, makes the verdict bracket-independent), bar = `TakeSkipCalibration.Bars[act, deck-size-excess bucket]` + `SkipWeight` × 10 × max(0, learned skip probability − 0.5); all three travel in `OfferScore.Frame` (null for relics/shop: raw scale). Bars = quantile of the best card's score at winners' skip rate per bucket, fitted by `tools/calibrate_take_skip.py <takeskip.jsonl|.npz> <lift-centers.json> <model> --report …` on `OfflineAdvisorEvaluation --take-skip` output (`d` raw, `t` framed delta) with `--lift-centers <metrics dir> <catalog>`; report `docs/take-skip-calibration-report.json`. After any change replay a part of the corpus and check the advised skip rate per act with the real C# (`t`), also with the a10 metrics as the global file.
- `src/SpireCodexMetricsClient.cs`, `CardCatalogClient.cs`, `RelicCatalogClient.cs`, `PickCoachClient.cs` — network + disk cache; every request goes through `NetworkSettings` (offline mode).
- `src/CardUpgrades.cs`, `TierOverrides.cs`, `PersonalRunDiary.cs`, `ArchetypePreferences.cs`, `RunHistoryInsights.cs`, `SegmentRiskModel.cs`.
- `src/AdviceOverlay.cs` — all UI (panel, badges, search, F8 hotkey via `FrameTicker`). `src/UiStyles.cs` — 7.3 selectable styles (`UiStyles.All`: parchment + ironclad, silent, defect, regent, necrobinder; palette, panel/seal shape; saved in `ui-style.json`; regressions always see Parchment) and `UiOrnaments` (header details as plain polygons → `AdvisorTheme.Decorate/Animate`, Polygon2D/Line2D + tweens; the footer "Стиль" chooser calls `AdviceOverlay.Restyle`, which rebuilds seal and panel). Tier colours never depend on the style. Preview of all styles: `docs/images/styles.png` (rendered from the palette by a scratch HTML page, not from the game). `src/AdvisorTheme.cs` — the 6.24 "Parchment" look (owner's choice, variant B): colours, bundled fonts (`assets/fonts`, OFL), panel theme, wax-seal button at the left edge, paper ribbons, hover cards. Panel geometry constants (`PanelX/Y/Width/Height`, `ContentWidth`, `BodyY`, `FooterY`) are at the top of `AdviceOverlay`.
- `src/BuildAdvisorRegression.cs` — regression matrix; runs at game start and via `tools/RegressionRunner`.
- `tools/` — offline evaluation and model training scripts, release scripts. `data/` — bundled models.
- `docs/ROADMAP.md` — the improvement plan (light / medium / heavy, status per task). `docs/DEVELOPMENT.md` — architecture and safe-change rules.

## Rules for every change

1. **Regression first.** Every behaviour change gets a positive and a negative scenario in `BuildAdvisorRegression.cs` and is added to `Run()`. Then mutation-check it: temporarily break the logic, confirm `Regression=False`, restore.
2. **Hermetic tests.** While `BuildAdvisorRegression.IsRunning`, personal data is ignored (diary, local `.run` files, tier overrides). New personal-data features must respect the flag. Tests must not write user files (no `NetworkSettings.Offline = …`, no diary saves).
3. **No Godot calls in testable logic.** `GD.Print`, `ProjectSettings`, nodes crash outside the engine. Keep them in UI/patch code or behind paths the tests never reach.
4. **Async.** Continuations return to the Godot main thread through its sync context; parse JSON with `await Task.Run(...)`. Check `GodotObject.IsInstanceValid` after every await. Swallow `OperationCanceledException` separately from other errors.
5. **Reflection.** Use `ReflectionIds.Member` (cached getters, safe with hidden properties). Prefer typed game API when it exists — verify it in `sts2.dll` first (the game ships `sts2.xml` docs next to it).
6. **Network data.** API rates are percent (43.0), scale is decided per response. Validate a payload before writing the cache; never cache an empty response.
7. **Build must be warning-free** (`-warnaserror` in the release script).

## Localization

User-facing text is Russian in code. English mode replaces substrings using `English` in `src/ModLocalization.cs` (longest key first, case-insensitive). For every new Russian string add a `("русский", "English")` pair; the regressions `EnglishAdviceHasNoRussianFragments` and `NewTextIsTranslated` fail on leftover Cyrillic. Server texts (Pick Coach) are requested in the UI language.

## Versioning and release

`major.minor.patch`: new or changed user behaviour → minor, fix without behaviour change → patch. The version must match in `build-advisor.json`, `BuildAdvisor.csproj` `<Version>`, `ModVersion.Current` in `src/BuildAdvisorMod.cs`, the `README.md` title and a `## X.Y.Z — date` entry at the top of `CHANGELOG.md` (the release script refuses otherwise). Also bump `INSTALL_*.md` and `PUBLICATION_CHECKLIST_RU.md`, mark finished tasks `✅ X.Y` in `docs/ROADMAP.md`, then commit and tag `vX.Y.Z`.

Commit messages: imperative subject `X.Y.Z: summary`, body with what changed and what was verified.

- Spire Codex brackets: only `all`, `a10`, `wr30`, `wr50`, `wr75`; `a0`..`a9` return 400 `unknown bracket` (`RunContext.Bracket` maps A<10 to `all`). Version brackets (7.5): a game version (`v0.111.0`) or a composite (`a10:v0.111.0`, `wr50:v…` is tiny) works on `/api/runs/metrics/{cards|relics|potions|events|campfires}`, also with `character`; `/api/runs/versions` → `stat_versions` (versions with a slice). A version without a slice answers with all runs and no data (`data_through` null, `lift_n` 0) — probe before use (`StatsVersion.IsUsable`). `/api/exports/runs?version=&limit=&cursor=` → gzipped raw runs (`X-Next-Cursor`); `?version=` alone redirects to the daily static file `/exports/runs-<version>.jsonl.gz` (reliable; the paged pull gave 504 on 2026-11-24); pages of 20,000 time out (504), 5,000 work; an older version needs `start=` a date when it was the current one (v0.111.0 from 2026-08-10 or without start: 504; from 2026-11-01: 1,000 runs in 17 s); use pages of 1,000. Cards take `include_skip`; relics accept `act` but ignore it. Ancient events are not in `events`.
- Rest site: `NRestSiteRoom.Options` (`RestSiteOption.OptionId` = HEAL, SMITH, MEND, DIG, LIFT, HATCH, CLONE, COOK, KINDLE — same keys as `/api/runs/metrics/campfires`), `HealRestSiteOption.GetHealAmount(Player)` is public static; `RestSiteOption.Owner` is not public. Campfire lift is survivor-biased (Rest −2 pp, 65 % of rests at low HP): never decide on it.
- Relic choice: `NChooseARelicSelection` holders are `NRelicBasicHolder.Relic.Model`. `/api/runs/metrics/relics` ignores `act`. Game over: `NGameOverScreen._history` (`RunHistory.Win/Seed/WasAbandoned`), `_runState.TotalFloor`. Card portraits: `ModelDb.AllCards` → `CardModel.Id.Entry`, `HasPortrait`, `PortraitPath`.
- Map: `NMapScreen.Open` (postfix), `_mapPointDictionary` (MapCoord → NMapPoint), `_bossPointNode`, `_secondBossPointNode`, `_startingPointNode`, `IsOpen`; `NMapPoint.Point` → `MapPoint.Children`, public field `coord`. The grid (`NCardGrid`) recycles holders while scrolling; the drawn card is `holder.CardNode.Model` (the holder's `CardModel` can be stale), the holder showing a card is `NCardGrid.GetCardHolder(model)`; grid badges are children of the holder (global-coordinate followers drift for rows outside the scroll window), the card node is centred on the holder.
- `/api/runs/encounter-stats?act=&room_type=&bracket=` accepts only `a10`/`wr*` (others → 400 "bad bracket"); rows have `avg_damage`, `fatal`, `total`, per-character rows. A10 averages: act 1 monster 9.7 / elite 27.9 / boss 46; act 2 17.4 / 35.3 / 54.5; act 3 14.3 / 28.5 / 62.5.
- `/api/runs/archetypes?lang=` → `characters.{IRONCLAD…}[]` clusters (`name`, `share`, `win_rate` percent, `defining_cards`, `defining_relics`); Pick Coach returns `candidates` in the same shape with `similarity`. Clusters with win rate < 1 % are undeveloped decks (runs that die early).
- Card selection screens: purpose comes from the screen type (`NDeckUpgradeSelectScreen`, `NDeckTransformSelectScreen`, `NDeckEnchantSelectScreen`, `NDeckCardSelectScreen`, `NSimpleCardSelectScreen`, `NCombatPileCardSelectScreen` = combat); never from all labels (card descriptions contain "Улучшает"). In combat (`CombatManager.Instance.IsInProgress`) no selection advice. Map labels are children of `NMapPoint`. `NGridCardHolder` and `NCard` are pooled (`IPoolable.OnFreedToPool/OnReturnedFromPool`): anything attached to a holder must be an `AttachedBadge` (removes itself when it leaves its screen) — 6.22.5 badges travelled to combat choices. Reward badges are children of `NCardRewardSelectionScreen.GetCardHolder(card)`; shop badges are children of `NMerchantSlot` above its `Hitbox`.
- **No Godot virtual overrides in mod classes.** The mod is built without the Godot C# source generators: the engine never calls `_Process`, `_Ready`, `_Input`, `_ExitTree` of the mod's own `Node`/`Control` subclasses (inferred: the DLL has no generated `InvokeGodotClassMethod`, and F8 never worked before 6.22.7 — confirm in game). Per-frame work goes through `FrameTicker.Add(Func<bool>)` (`SceneTree.ProcessFrame` signal); lifecycle through signals (`TreeExiting`, `MouseEntered`). Godot tooltips (`TooltipText`) do not show in this game: use `AttachedBadges.EnablePopup`.
- Archetypes are matched on `CardDefinition.Signals` (catalogue `vars`, `powers_applied[].power_key`, `keywords_key`, `spawns_cards`) plus localized text; Russian game terms: Exhaust «сжигает»/«стопка пепла», Doom «злой рок», Forge «закаляет», Frost «сфера льда», Strength «силы». - Take/skip (7.3.1): 7.2 bars were fitted on `all` lifts; in game A10+ uses `a10` (median lift 7.2 vs 9.1, IQR 7.3 vs 5.9) and per-character own-card medians differ a lot (defect 5.6 in `all`, 2.0 in `a10`; silent 10.2 / 7.3) → nearly every card negative at A10. Objective used: advised skip rate within ±3 pp of winners', maximise agreement with winners' take-or-skip decisions (unconstrained fits drift to pure imitation of the skip model or to skipping half the rewards). Outcome check where 7.1 and 7.2 disagree is confounded by player skill (skippers are better players) — treat as association only.
