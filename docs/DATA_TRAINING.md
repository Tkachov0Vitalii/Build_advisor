# Данные и повторное обучение

## Что находится в установленном моде

`build-advisor-run-priors.data` — компактный JSON с агрегатами. Текущая версия сформирована из 177 248 валидных полных забегов и 2 132 320 решений по картам. Из них 140 216 забегов использованы для обучения, 19 390 — для validation и 17 642 — для финального test. Файл содержит:

- медианный размер победной колоды для персонажа и этажа;
- для каждой карты число забегов с одной и несколькими приобретёнными копиями;
- предпочтение следующей копии при реальном предложении с учётом акта и числа уже имеющихся экземпляров;
- количество побед внутри обеих групп;
- дату генерации, версию схемы и общее число обработанных забегов.

Файл не содержит никнеймы, Steam ID, сиды, последовательности комнат или полные колоды отдельных игроков.

## Можно ли удалить сырые забеги

Да, если требуется только запуск текущей версии мода. DLL загружает агрегаты из папки мода и не обращается к каталогу исходных забегов.

Рекомендуемый вариант — сжать сырые данные и хранить одну контрольную копию. Они понадобятся для:

- пересчёта после изменения формулы;
- обучения по порядку выбора карт и состоянию колоды в момент выбора;
- разделения результатов по версии игры, сложности и персонажу;
- независимого теста модели на забегах, которые не участвовали в расчёте;
- поиска ошибки в исходном парсере.

## Пересчёт приоров

В репозитории есть два эквивалентных обработчика:

```powershell
py tools\analyze_model_corpus.py "D:\ран\build-advisor-model-200k" "work\model-corpus"
```

или при доступном Python:

```powershell
py tools\evaluate_model_corpus.py "work\model-corpus\model-corpus-report.json" --output "work\model-corpus\model-evaluation.json"

py tools\export_model_priors.py "work\model-corpus\model-corpus-report.json" "work\model-corpus\model-evaluation.json" "build-advisor-run-priors.data"
```

Обработчик читает старые `.run` и новые `.json` рекурсивно, пропускает повреждённые файлы, заброшенные партии и служебные JSON-файлы. После генерации обязательно проверьте значения `runs`, `duplicates`, дату и размер файла.

## Ограничения текущего обучения

Статистика наблюдательная: высокая победность дубликатов не доказывает, что именно дубликат вызвал победу. Сильные игроки, редкость карты, акт получения и уже сложившийся архетип создают смешение факторов. Поэтому историческая поправка ограничена и не может полностью отменить структурный штраф за лишнюю копию.

Текущая контекстная модель улучшила Brier относительно общей вероятности персонажа/акта на 8,04% на validation и на 7,96% на test. Это измеряет качество предсказания реального выбора, но не доказывает причинный прирост победности. Поэтому коэффициенты используются как ограниченная поправка к игровой логике, а не как безусловная замена экспертной оценки.

При первом прогоне была обнаружена утечка ответа: выбранная на текущем этаже карта уже попадала в состояние колоды «до выбора». Этот результат был полностью отброшен; опубликованные показатели получены только после исправления и повторного полного расчёта.

## Модель риска ближайших трёх узлов

```powershell
py tools\train_segment_risk_model.py `
  "D:\ран\build-advisor-model-200k" `
  "work\model-corpus\corpus.snapshot.sqlite3" `
  "work\model-corpus\segment-risk-v1.json"
```

Скрипт сохраняет разделение по группе игрока, обучает модель только на train, выполняет Platt-калибровку только на validation и публикует Brier, log loss, ECE и reliability bins для test. Итоговый JSON копируется в мод как `data/segment-risk-v1.data`; сырые забеги для работы мода не нужны.
